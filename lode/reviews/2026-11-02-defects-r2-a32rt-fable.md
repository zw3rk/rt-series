## Section 3 — Remaining or Newly Introduced Consequential Findings

- **N1 — Medium — BUG (liveness) — PLAUSIBLE — Cache reset can stall behind a guest busy-loop holding a reader lease.** `a32_jit_reset_cache_locked` spins for `g_jit_exec_readers == 0` while holding `g_jit_lock` (`vm_jit_mem.c:112-116`). A thread whose translated block (or chain of blocks) spins on guest memory without exiting to the dispatcher keeps its lease; if the thread blocked in reset is the one that would release that spin, every thread hangs on the JIT lock. Epoch 0 is published before the wait, so chain sites that poll `*epoch_ptr` will bail out; whether *single-block self-loops* (`self_loop_vfp_active` exists in the emitter) also poll the epoch was not verifiable within budget. **Follow-up:** confirm every backward branch/self-loop polls the epoch, or add a bounded host-side kick (e.g., `tgkill` with a no-op handler forcing block exit) before the drain.

- **N2 — Medium — BUG — PLAUSIBLE — On A2, the unreserved host-page tail of a `MAP_SHARED` mapping can be claimed by a later private mapping, and the replacement path writes into it.** The shared region is recorded with `aligned_len` while only `gap_len` is placed; `vm_find_free_gap_locked` avoids the tail, but the hint path and `MAP_FIXED` (non-shared) path consult `vm_range_overlaps_locked` only (`vm.c:1163-1193`), which does not see the tail. A private 4 KiB mapping placed there takes `a32_backend_map_anon`'s sub-page replacement branch: `mprotect(host page, RW)` + `memset(hint, 0, len)` (`backend_darwin.c:79-93`), i.e. zeroing bytes of the native shared file mapping (file corruption for writable shared files, or SIGBUS past EOF). The R2-3 "reject layouts that cannot preserve neighbours" half is therefore still open. **Follow-up:** record the shared region (or a synthetic guard region) at `gap_len`, or make `vm_range_overlaps_locked` host-page-aware for shared neighbours.

- **N5 — Medium — DEFECT — CONFIRMED by code — `MAP_SHARED|MAP_ANONYMOUS` now depends on a writable `/tmp` in every regime.** `vmfile_create_shared_anon_fd` hard-codes `mkstemp("/tmp/a32-shanon-XXXXXX")` (`vm_file.c:1690-1707`) and is used on Linux A1 as well, where native `MAP_SHARED|MAP_ANONYMOUS` was already correct. In a container, chroot, or `hl` sysroot without `/tmp`, every shared-anon `mmap` fails; on a disk-backed `/tmp` it also changes performance characteristics. **Follow-up:** use `memfd_create` on Linux (`A1`) and keep the temp-file path for Darwin only, honouring `TMPDIR`/`A32RT_CACHE` with a fallback.

- **N3 — Low — C11 — CONFIRMED — Lock-free side-table reads race ring-slot overwrites.** `a32_jit_lookup_host_pc` now reads `g_side_table[]` fields without synchronisation while `a32_jit_commit_side_table_locked` may overwrite wrapped slots on another thread (`vm_jit_state.c:2116`, `vm_jit_mem.c:2082-2102`). Formally a data race; practically benign unless the ring wraps during a fault lookup. Net improvement over the previous signal-unsafe lock. **Follow-up:** per-entry generation/seqlock, or copy-on-reset only under the reader drain.

- **N4 — Low — BUG — CONFIRMED — `PR_SET_NAME` reads one byte more than Linux.** The loop reads index 15 before accepting a 15-byte unterminated name (`os_sys_fs_arm.c:429-440`); Linux (`strncpy_from_user(..., TASK_COMM_LEN-1)`) reads at most 15 bytes. A name whose 16th byte lies on an unmapped page gets a spurious `EFAULT`.

- **N7 — Low — DEFECT — CONFIRMED — Beyond-EOF access raises SIGSEGV, not SIGBUS.** `A32_PROT_EOF_CUT` pages are `PROT_NONE` (A1) or `-EFAULT` on TLB miss (A2); Linux delivers `SIGBUS` for a mapped-but-past-EOF page. Also, the partial last page is zeroed only when guest-writable, so a read-only mapping retains stale tail bytes after shrink.

- **N6 — Info — Hygiene** — Reader-lease handshake (`a32_jit_exec_enter` RMW `acq_rel` + `acquire` load vs. writer `seq_cst` store + `acquire` load) is correct under AArch64 RCsc STLR/LDAR but is not formally the C11 `seq_cst` store-buffering pattern. Document the AArch64-only assumption or make both sides `seq_cst`.

**Verification limits:** no build or test run was performed (Nix-driven toolchain and `hl`/lima oracles were out of budget); golden-file changes are taken on faith. N1 and N2 are source-supported and not reproduced; their severity reflects the consequence if triggered (hang; shared-file data corruption on A2), not an observed failure.
