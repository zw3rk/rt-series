## Section 1: Per-Finding Verification Table

| ID | Title | Status | Technical Notes |
|---|---|---|---|
| P64-R2-1 | Cooperative children lack general scheduling; instruction cap | **INCOMPLETE** | Substantially improved: `P4_TASK_STEP_CAP` removed; `run_cpu` now calls `syscall_p4_sched_tick` every 4096 main-task steps when ready tasks exist (`src/run/core.c:345-361`); `sched_yield` ticks the scheduler; clone runs ≤4 rounds. Remaining gaps: (a) the tick is gated on `syscall_p4_has_ready_tasks()`, so futex waiters with a pending deadline or signal-wakeable state are never re-evaluated while the main task spins on ordinary memory (see R2-3); (b) `run_until_event` (difftest runner) received exit routing but no periodic tick, so a parent busy-waiting on a child-written flag still starves children there; (c) blocking host syscalls issued by a child still block the whole process (inherent to the single-host-thread design, not fixed); (d) **re-entrancy**: `syscall_p4_clone` called from a *child* task invokes `p4_sched_run_ready` while `s_cur_task != NULL`; the running child is still `P4_TASK_READY`, so the nested scheduler re-steps the caller's own `cpu` before the outer frame applies the clone return value. The futex WAKE path guards this with `s_cur_task == NULL`; clone does not. Pre-existing, but now more reachable since children run through the full syscall path. |
| P64-R2-2 | Thread exit vs. thread-group exit scope | **VERIFIED** | `exit` → `syscall_p4_exit`: finishes only the current task, or marks main exited, clears main's clear-TID word, and keeps scheduling surviving tasks until group exit or quiescence; status = group code or last task's `exit` code (matches Linux semantics for a leader that calls `exit`). `exit_group` → `syscall_p4_exit_group` sets `s_group_exited`, frees all tasks, propagates `PPC64_SYSCALL_EXITED` through clone/futex/tick callers and both runners. Minor: when main has exited and all children are futex-blocked with no deadline, the loop breaks and returns rather than hanging (Linux would hang); acceptable for a deterministic emulator. `run_until_event` still sets `ev->r3 = ev->args[0]` rather than the resolved status (cosmetic). |
| P64-R2-3 | Futex timeout validation does not implement timeout behavior | **INCOMPLETE** | Deadlines are now stored per task (`has_deadline`, `clock_realtime`, `deadline_ns`); relative WAIT uses `CLOCK_MONOTONIC`, WAIT_BITSET uses an absolute deadline with `FUTEX_CLOCK_REALTIME` selection; expired waiters get `ETIMEDOUT` via `p4_check_futex_deadlines`; signal arrival yields `EINTR`. Two defects remain: (a) deadlines are evaluated only inside scheduler entry points, and the main-loop tick is skipped unless a task is already READY, so a child in a timed WAIT while the parent spins without syscalls never times out → hang; (b) when nothing is runnable, `force_earliest=true` immediately expires the earliest waiter regardless of wall clock, and the untimed main-task WAIT still returns EAGAIN on an empty ready queue. ## Section 3: Remaining or Newly Introduced Consequential Findings

1. **Nested clone from a child task re-steps the running task (High, pre-existing but now more reachable)**. `syscall_p4_clone` → `p4_sched_run_ready` with `s_cur_task != NULL`; the caller remains `P4_TASK_READY` and is re-entered by the nested scheduler before its clone return value is applied (`src/os/syscalls_p4.c:551-593`). Fix: mark the running task with a distinct `RUNNING` state (or skip `s_cur_task`) in every scheduler loop, and defer scheduling to the outer quantum when invoked from a child.

2. **Timed futex waiters are never expired while the main task runs without syscalls (High, from R2-3)**. `run_cpu` only ticks when `syscall_p4_has_ready_tasks()`; deadline evaluation lives only inside scheduler entry points. A child in `FUTEX_WAIT` with a timeout while the parent spins on memory hangs forever. Fix: tick when any task is waiting with a deadline (or pending unblocked signal), not only when one is READY; apply the same tick to `run_until_event`.

3. **`ppc64_vm_file_mremap` mishandles partially-overlapping and shrinking file-map records (Medium, new)**. Map records that only partially overlap `[old_addr, old_end)` are skipped (`src/vm/vm_file.c:323-325`) and remain tracked at the old VA after `syscall_unmap`, which the removed `ppc64_vm_file_untrack_range` calls previously handled. For a fully-contained record when `new_size < old_size`, `gva_end` is relocated to `new_addr + old_size`, extending the record past the new mapping. Fix: split/truncate partially-overlapping records (or fall back to untracking them) and clamp `gva_end` to `new_addr + new_size`.

4. **Possible stale host pointer in the aligned atomic path (Medium, PLAUSIBLE, unverified)**. `host` is obtained before `ppc64_vm_cow_promote_range` (`src/vm/vm_atomic.c`). If promotion can swap the page's host backing, the CAS writes to the old page. Confirm that promotion is state-only under the in-place page model; if not, re-fetch `host` after promotion.

5. **Deterministic early timeout is undocumented (Low)**. `p4_check_futex_deadlines(…, force_earliest=true)` expires the earliest waiter immediately whenever the system would otherwise idle. This is a defensible design choice for determinism, but it contradicts the R2-3 fix guidance and should be stated in the module header and in `SPEC.md`.

6. **FPSCR fidelity gaps (Low)**. VX sub-flags beyond VXSNAN, the FR bit, and FX 0→1 transition semantics are still approximate. Rounding correctness relies on `volatile` without `-frounding-math`; add it to `CFLAGS` for `fp.c` or document the reliance.

Residual Round-2 items that are design limits rather than defects: children never run under DBT; blocking host syscalls in a child stall the group; `faccessat` flags are ignored.
