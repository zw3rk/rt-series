## RC-U5-lanes (fable#high) — verdict: ACTION_REQUIRED

All three branches merge cleanly except for a guaranteed 3-way conflict at the Makefile tail. None of the three delivers the integration its task card asks for: U5-A's Provider A and U5-B's DBT are standalone modules with host unit tests and no runtime caller, and U5-C's RV32 syscall surface is far narrower than "complete ILP32D". Evidence in `_build/` shows the host unit tests and runtime builds were run, but the card-specified acceptance targets are unverified from the artifacts alone.

What is correct and can be kept: the D13 BF16 NaN mask (`internals.h:110`), the D15 owner-wake fix (`scheduler.c:491-494`) with its regression test, the D1 falsification (Linux `fdget` rejects `FMODE_PATH` before any offset check, so EBADF is right and DEFECTS.md D1 should be closed as not-a-defect), the RV32C expansion table (`rv32_expand.c`, checked against the RVC spec), the RV32 interpreter arithmetic and shift semantics, the ELF32 loader and ILP32 auxv, and the AOT v4 record encoder/decoder structure apart from the bounds bug below.

### P1

- **U5-B `src/dbt/emit_mem.h:137-145,148`.** Eight of the eleven pinned load/store words encode base register x0 instead of x1. Assembling `ldrb w0,[x1,x3]` gives `0x38636820`; the header pins `0x38636800`, which is `ldrb w0,[x0,x3]`. Same for LDRH, LDRW, LDRSB, LDRSH, LDRSW, STRB, STRH. The 7-instruction fast path therefore accesses `value_reg + addend`, not `guest_addr + addend`. No test executes emitted words; `test/u5b_dbt_mem.c:176` compares against the same constant.
- **U5-B not integrated.** `src/dbt/*` is absent from `RUNTIME_SOURCES` (`Makefile:553-556`) and nothing outside `src/dbt/` references it. `src/dbt/difftest.c:85-117` drives the legacy `rv_jit_compile` in `src/jit/a64.c`, not the DBT. The card's acceptance targets `test-aot-cache-rebase`, `test-aot-multiblock`, `test-aot-dynamic` (`Makefile:8156,8411,8455`) were replaced by host-only `test-u5b-*` aliases (`Makefile` +8559..+8568). `rv_dbt_enter` is never linked.
- **U5-A not integrated.** No file outside `src/vm/` and `src/os/` references vm64, vm_file or `rt_host_*`; `runtime_main.c` is untouched. Key requirement 1 of the card (route `CLONE_VM`, `mmap`, `write`, `ftruncate` through vm64 + Provider A, remove the `progress_turn_wait` deadlock) is not delivered; only the one-line D15 fix landed. U5-D's broker retirement has no replacement path to switch to.
- **U5-A `src/vm/vm_file.c:154-169` with `src/vm/vm64.c:184-203`.** `record_shrink` passes the new file size as `shrink_end`; the only discard implementation treats it as a guest VA and zeroes every `COW_DIRTY` page in the whole arena at or above that address, for every file. There is no inode-to-mapping association. The smoke test passes only because its anon pages are not DIRTY (`test/u5a_vm_provider.c:109-111`).
- **U5-C `src/linux/signal.c:432-440,462-472`.** RV32 `struct sigaction` is read as 20 bytes with `sa_mask` at +12. Linux riscv32 has no `sa_restorer`: handler u32 at 0, flags u32 at 4, mask u64 at 8, 16 bytes total. musl's rv32 `k_sigaction` has the mask at +8 too. Every non-empty handler mask is wrong and 4 bytes past the guest struct are read. The fixture hard-codes the lane's layout with a zero mask (`test/fixtures/u5c-sig.S:24-31`), so the qemu oracle cannot see it.
- **U5-B `src/dbt/aot_v4.c:427-437`.** `at = 180 + modules*40` is never checked against `encoded_size` (header only guarantees 180 bytes, modules up to 64). `encoded_size - at` underflows and the loop reads out of bounds. A truncated or crafted cache crashes instead of returning `FAULT`.

### P2

- **U5-A `src/linux/poll.c:446-449` (D8).** Returning EINVAL for nfds > 1024 diverges from Linux, whose `core_sys_select` silently clamps to `max_fds`. The old clamp matched the kernel because the guest table limit is 1024. Guests passing `sysconf(_SC_OPEN_MAX)` now fail. Revert and close D8 as not-a-defect.
- **U5-A `src/vm/vm64.c:105-121`.** `map_anon` only mprotects: a re-mapped range keeps stale contents, and a range previously mapped from a file stays file-backed while marked ANON. No unmap entry point. `map_private_file` ignores guest prot (always RW at 4 KiB hosts, never protected at 16 KiB hosts).
- **U5-A `src/vm/vm_file.c:128-144,102-106,247`.** `retained_fd` is a per-process descriptor number stored in a cross-process MAP_SHARED table; siblings that did not inherit it fstat the wrong fd, and `table_destroy` closes those numbers in whichever process runs it.
- **U5-A `src/vm/vm_file.c:179-190`.** `note_write_after` bumps `code_generation` only on growth. In-place writes to mapped code pages never invalidate, contrary to `vm_file.h:49-53` and the U4-B write-invalidation list.
- **U5-B `src/dbt/cache.c:212-234,101-104`.** `rv_dbt_invalidate` ignores `start` (kills every block with base < end) and never reclaims `used` or slots; after 512 adds translation stops permanently. No full clear exists despite `cache.h:263-265`.
- **U5-B `src/dbt/aot_v4.c:535-552`.** `warm_check` compares only `input_digest`. Runtime, emitter and profile digests and generation are ignored, so a cache from a different emitter build is a HIT.
- **U5-C RV32 syscall conventions.** `mmap` offset is in pages on rv32 but `src/runtime/mm_runtime_binding.c:15-21` treats it as bytes and rejects every non-zero-offset DSO segment with EINVAL (the dynamic fixture survives only because ld-musl is libc.so itself; `_build/u5c/sysroot/lib/libc.so` has four PT_LOADs at non-zero offsets). `_llseek` 5-arg form (`file.c:1471`), split a4:a5 offsets for pread64/pwrite64/ftruncate64 (`file.c:1467-1476`), time64 numbers other than 403 (`misc.c:298`; futex 422, clock_nanosleep 407, ppoll 414, pselect6 413, utimensat 412) and statx are absent, and pre-existing RV32 ENOSYS gates remain in `sleep.c:207` and `poll.c:167,390`. The qualified surface is seven raw fixtures plus a hello-world.
- **U5-C `src/linux/rv32_frame.h:21-22`.** `uc_stack` at 144 and `uc_sigmask` at 160 do not match the rv32 kernel layout (136 and 148). `uc_mcontext` at 288 and the 944-byte size do match. Self-consistent with rvrt's own sigreturn, but guest handlers that inspect `uc_stack` or `uc_sigmask` see wrong fields.
- **U5-C `src/core/interp.c:167,195`.** FLW/FLD/FSW/FSD effective addresses skip `rv_ea`, unlike integer loads and stores at lines 157 and 186.
- **U5-C ownership.** The lane edited `src/core/{interp,decode,compressed,fp}.c`, `internal.h`, `profile.h`, `src/jit/a64.c` (U5-B), `src/linux/{io,message,misc,signal}.c` (signal.c is U5-A), `src/loader/{image.c,image.h,stack.c}`, `src/runtime_main.c` (U5-D) and `Makefile` without escalation. Textual merges are clean except the Makefile.
- **Integration.** Makefile: all three append after line 8520; a simulated merge conflicts at lines 8522-8636. Resolve by concatenation. Two `--difftest` implementations exist (`runtime_main.c:5207-5238` inline vs `src/dbt/difftest.c`). U5-A's `RUNTIME_SOURCES +=` at `Makefile:8522` comes after the immediate expansions at lines 553, 567 and 924, so the new files are linked by the recipe but are missing from prerequisites and from object-mode builds. `build-darwin: build` is an acceptance substitution. The D15 fix lands in `scheduler.c`, which U5-D is slated to retire.

### P3

- `src/runtime/scheduler.h:65-67` comment (D14) still omits the owner exclusion. DEFECTS.md D1 disposition and D3 (ppoll contract text) need coordinator action.
- `src/os/backend_linux.c:221` uses SIGRTMIN+1 for preemption while `src/runtime/native_signal.c:1213` uses SIGRTMIN as the stop signal; confirm no collision with guest-visible RT signals. `backend_darwin.c:197-211` maps Linux `MADV_DONTNEED` to Darwin's, which does not zero-fill.

- `src/dbt/emit_mem.c:71,81` emit a single 8-byte access for width 16; `emit_mem.c:147-148` admits a cbnz delta of exactly 1 MiB (one past imm19 range); `emit_mem.c:198-201` classifies some fences as AMO helpers; `difftest.c:47-83` ignores f-registers.

- `test/u5c-rv32-parity.py:160-163,204-207` apt-installs qemu inside a container on every run; `test/u5a_limactl_shim.sh` is unreferenced.
