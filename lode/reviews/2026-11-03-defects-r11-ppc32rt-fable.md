### P32-R11-1: failed `rt_sigreturn` re-executes `sc` forever — **VERIFIED**

The fix has two parts that work together:

1. **`sys_rt_sigreturn`** (`signals.c:616-643`): On `ppc32_sig_restore_frame` failure (`r < 0`), attempts `ppc32_sig_deliver_sync(SIGSEGV)`. If the guest has a SIGSEGV handler, it's entered (`dr == 0`, return `0L`). If no handler, parks `exit_reason = PPC32_EXIT_FAULT` before returning, ensuring the driver sees a fatal stop.

2. **`syscall_dispatch` and `run_guest_child`**: The unconditional `ctx->exit_reason = PPC32_EXIT_NONE` reset is now guarded by `if (ctx->exit_reason == PPC32_EXIT_SYSCALL)` at `main.c:525-527` and `main.c:474-476`. This preserves the `EXIT_FAULT` parked by `sys_rt_sigreturn`, so the main loop falls through to `report_stop()` instead of re-executing the `sc`.

The `ppc32_sig_nr_no_advance` path (no nip += 4 for `NR_RT_SIGRETURN`) is correctly preserved at `signals.c:700-702`.

### P32-R11-2: `kill(getpid(), 0)` returns `-EINVAL` instead of 0 — **VERIFIED**

`ppc32_sig_kill` (`signals.c:714-722`): The lower-bound check changed from `sig < 1U` to no lower check — only `sig > PPC32_NSIG` rejects. A new `sig == 0U` branch at line 718-722 returns 0 for self-probe (`pid == getpid()`), and forwards to host `kill(pid, 0)` for foreign pids, correctly propagating errno. This matches the kernel behavior where `sig == 0` is an existence check.

### P32-R11-3: `SIG_IGN` on synchronous fault loops — **VERIFIED**

`ppc32_sig_deliver_sync` (`signals.c:466-471`): Inside the `SIG_IGN` handler branch, a new check for the five synchronous-fatal signals (`SIGSEGV`, `SIGBUS`, `SIGILL`, `SIGFPE`, `SIGTRAP`) returns `-EFAULT` instead of `1` (re-execute). The driver at `main.c:411` treats any return other than 0 or 1 as undeliverable, correctly falling through to termination via `report_stop()`. Async `SIG_IGN` is unaffected — it's discarded in `pump_pending` (line 770-772) before reaching this code.

### P32-R11-4: `rt_sigaction` accepts new disposition for SIGKILL/SIGSTOP — **VERIFIED**

`sys_rt_sigaction` (`signals.c:527-530`): New guard `if (!ppc32_sig_is_catchable((int)sig)) return -EINVAL;` fires before `ppc32_sigaction_set_raw`. `ppc32_sig_is_catchable` at `signals.c:81-83` returns 0 for `SIGKILL` and `SIGSTOP`. Queries with `act_va == 0` bypass the check since `have_new == 0`, matching the kernel.

**Minor fidelity note:** The old action is written to `old_va` (lines 520-525) *before* the catchable rejection (line 528). The kernel checks catchable first (`act && sig_kernel_only(sig)` before writing `oact`). This means ppc32rt writes the old action even when it returns `-EINVAL`. Not a functional defect — no sane program depends on old not being written on error — but differs from kernel ordering.

### P32-R11-5: SIGTRAP frame reports trace vector 0xD00, should be 0x700 — **VERIFIED**

`sig_default_trap` (`signals.c:423-424`): The `PPC32_SIGTRAP` case now uses `PPC32_TRAP_PROGRAM` (`0x700U`, `signals.h:110`) instead of `PPC32_TRAP_TRACE` (`0xD00U`, `signals.h:111`). This matches the PowerPC ISA: `tw`/`twi` instructions raise the Program exception at vector `0x700`; `0xD00` is the debug/trace exception never generated by this emulator.

`PPC32_TRAP_TRACE` is now dead code — defined at `signals.h:111` but referenced nowhere. Minor cleanup opportunity.

The comment at `hostfault.c:129-133` explicitly documents this as load-class default with DBT store direction deferred. Guest programs running under `--dbt` that inspect `mc_gregs[42]` (DSISR) in a SIGSEGV handler for a store fault will still see the load class.

### Newly Introduced Issues

1. **`pump_pending` silently drops delivery failure** (`signals.c:779-780`): Changed from `if (deliver_sync == 0) return` (retry next signal on failure) to `(void)deliver_sync; return` (unconditional return). If `ppc32_sig_build_frame` fails, remaining pending signals are skipped. In practice, a failed frame means a corrupted stack and all signals would also fail; the pending bits are preserved for the next pump call. Low risk but a behavioral change.

2. **`sys_rt_sigreturn` defensive null-check** (`signals.c:626-628`): `ctx == NULL` can never happen — the syscall dispatch always passes a valid context pointer. Harmless dead code.

3. **`PPC32_TRAP_TRACE` dead definition** (`signals.h:111`): Still defined but no longer referenced after the R11-5 fix. Cleanup candidate.
