I would revise both documents before starting the lanes. Several proposed fast paths can lose architectural state or execute stale code, and several central bottleneck claims describe code that has already changed. The benchmark results establish workload times; they do **not** yet establish the per-phase causes or the proposed speedups.

This was a read-only source review across all nine repositories. I did not run builds, tests, or benchmarks, and I did not change the two draft documents.

1. **Code-cache validation cannot yet be replaced by epochs alone.** [PERF-PLAN.md](/Users/angerman/Projects/zw3rk/rt-series/docs/PERF-PLAN.md:160) assumes every MIPS64 code-page write advances the SMC epoch, but [MIPS64’s lookup](/Users/angerman/Projects/zw3rk/mips64rt/src/dbt/dbt.c:328) explicitly retains byte snapshots for plain stores without an epoch bump. Similarly, [LoongArch’s hash](/Users/angerman/Projects/zw3rk/loongarch64rt/src/dbt/dbt.c:301) covers stores and AMOs that the mapping epoch misses. `vm64_mark_code` has no active callers under `src`, while the [Soft-TLB fill](/Users/angerman/Projects/zw3rk/loongarch64rt/src/dbt/dbt_mem.c:197) grants write tags from ordinary permissions without the code write-gate.

   Keep snapshots and hashes until the implementation marks every translated page, revokes already-filled writable tags **before** publishing code, and covers native and interpreter stores, atomics, syscall copyouts, aliases, remaps, and cross-thread visibility. Add a regression that fills a writable TLB entry, translates the page, modifies it through each writer, then immediately executes the modified code.

2. **PPC32’s syscall-flush removal needs a copyout audit first.** [P1.1](/Users/angerman/Projects/zw3rk/rt-series/docs/PERF-PLAN.md:55) proposes removing the unconditional flush, but [sys_read](/Users/angerman/Projects/zw3rk/ppc32rt/src/os/syscalls.c:111) writes directly into guest memory without an SMC notification. C-side [cache lookup](/Users/angerman/Projects/zw3rk/ppc32rt/src/dbt/cache.c:287) checks snapshots, but an already-linked predecessor can chain to the changed target without that lookup. First exempt syscalls proven not to write guest memory; invalidate actual written ranges for copyouts before removing the remaining fallback. Test a partial, cross-page `read` into a translated target reached through an existing link.

3. **The proposed chaining ABIs conflict with existing code.**
   - **RV:** [P2.3](/Users/angerman/Projects/zw3rk/rt-series/docs/PERF-PLAN.md:102) assigns the LUT to `x21`, which the emitter uses as the CPU pointer. Each current [block entry](/Users/angerman/Projects/zw3rk/rvrt/src/darwin_dbt.c:695) also pushes a frame and resets `w22`; branching to that entry repeatedly would grow the stack and reset the budget.
   - **MIPS32:** [P4.1](/Users/angerman/Projects/zw3rk/rt-series/docs/PERF-PLAN.md:138) assigns `x21` and `w22` to the table and budget, but they are emitter scratch/address registers. Existing [exit code](/Users/angerman/Projects/zw3rk/mips32rt/src/dbt/emit_int.c:120) also overwrites cached guest values in `w0` and `w1`.
   - **SPARC32:** [P5.2](/Users/angerman/Projects/zw3rk/rt-series/docs/PERF-PLAN.md:177) writes a code pointer into a slot that the [existing emitter](/Users/angerman/Projects/zw3rk/sparc32rt/src/rt32/a64_emit_fp.c:350) dereferences as metadata containing an epoch and code pointer. Slot reuse also needs incoming-link invalidation or a target-key check.

   Each card needs an explicit external-entry versus chain-entry contract, register allocation, stack/LR rules, and state reconstruction on misses and exits. Test all cached registers across hits, collisions, budget expiry, helpers, and faults.

4. **Chaining must preserve invalidation, fault metadata, and execution boundaries.** SPARC64’s proposed epoch-only LUT is insufficient: [precise invalidation](/Users/angerman/Projects/zw3rk/sparc64rt/src/dbt/dbt.c:805) bumps page versions and clears existing entries without necessarily bumping the global epoch. MIPS64 fault recovery uses the current block’s site metadata; a chained target must update the active block identity before it can fault. Chains must also retain bounded signal and quiescence polling, delay-slot restart semantics, and single-step behavior.

   Require tests for an invalidated chained target, cache-slot collision, signal delivery in a hot cycle, fault in the second chained block, and difftest with a branch and delay slot. Exercise normal chaining separately from tests that disable it.

5. **The i686 flag-elimination rule is unsound at intervening faults.** [P3.2](/Users/angerman/Projects/zw3rk/rt-series/docs/PERF-PLAN.md:122) considers whether the *producer* can fault after writing flags. It must also consider instructions between that producer and the overwriter. For example, `add eax,1; mov edx,[unmapped]; xor ecx,ecx` requires the signal handler to observe the ADD flags. A later memory RMW can likewise fault before committing its replacement flags; the current [ALU emitter](/Users/angerman/Projects/zw3rk/i686rt/src/dbt/emit_alu.c:381) stores the result before committing the lazy descriptor.

   Treat potential faults, traps, helpers, and observable exits as flag barriers unless deoptimization metadata can reconstruct the prior state. Track partial writes and reads, including preserved CF for INC/DEC, preserved flags for rotates, and zero-count shifts. Test signal-frame EFLAGS and retry after faulting loads and RMWs.

6. **The FP fast paths do not preserve status merely because traps are disabled.**
   - PPC32 [P1.2](/Users/angerman/Projects/zw3rk/rt-series/docs/PERF-PLAN.md:58) skips `fp_accum`, although the existing [emitter](/Users/angerman/Projects/zw3rk/ppc32rt/src/dbt/emit_fp.c:143) records sticky exception and summary bits. `fcmp result, 0` alone also cannot reproduce the FPRF class bit for all result classes.
   - MIPS’s proposed `(fcsr & 0xff) == 0` test misses exception-enable bits 8–11; the [MIPS32 emitter](/Users/angerman/Projects/zw3rk/mips32rt/src/dbt/emit_fp.c:377) extracts the full enable field. Cause and sticky flags remain observable with traps disabled.
   - LoongArch’s proposed `0x31F0000` mask misses rounding bits 8–9 and enable bits 0–4. Its existing [emitter](/Users/angerman/Projects/zw3rk/loongarch64rt/src/dbt/emit_fp.c:61) reads the rounding field and separately maintains cause and sticky flags. The [LoongArch manual](https://loongson.github.io/LoongArch-Documentation/LoongArch-Vol1-EN.html) specifies those fields and their per-operation behavior.
   - SPARC64 must replace `cexc` for the current operation and accrue `aexc`; a block-wide cumulative FPSR cannot recover the last operation’s `cexc`.

   Specify guest and host FP-environment ownership and exact materialization points at CSR reads, helpers, traps, signals, and exits. Test each exception, enabled and masked traps, nondefault rounding, subnormals, signed zero, infinities, and signaling/quiet NaNs.

7. **Enabling the dormant MIPS FP emitters is not a mechanical blocker removal.** MIPS32 caches `$ra` in `w15`, while [FP arithmetic](/Users/angerman/Projects/zw3rk/mips32rt/src/dbt/emit_fp.c:488) overwrites `w15` without its caller saving it. A non-leaf function can therefore lose its return address. MIPS64’s [emitter notes](/Users/angerman/Projects/zw3rk/mips64rt/src/dbt/emit_fp.c:39) also acknowledge deferred inexact, overflow, underflow, and divide-by-zero flags.

   Audit clobbers and complete or conservatively fall back for unsupported semantics before enabling these paths. Add a function that performs FP arithmetic and returns through `$ra`, plus FP branch, delay-slot, and trap tests.

8. **RV FP lowering needs more than result NaN-boxing and RNE.** [P2.1](/Users/angerman/Projects/zw3rk/rt-series/docs/PERF-PLAN.md:89) omits malformed input-box handling, sticky `fflags`, comparison-specific invalid exceptions, raw move/sign-injection behavior, conversion boundaries, and host FPCR/FPSR ownership. The existing [RV semantic layer](/Users/angerman/Projects/zw3rk/rvrt/src/fp/semantic.c:9) already distinguishes these cases. The [RISC-V F](https://docs.riscv.org/reference/isa/v20260120/unpriv/f-st-ext.html) and [D](https://docs.riscv.org/reference/isa/v20260120/unpriv/d-st-ext.html) specifications define accrued flags and input NaN-box checks.

   Add explicit tests for malformed boxes, qNaN/sNaN comparisons, all five flags and their accumulation, static/dynamic and reserved rounding modes, FMA cancellation, conversion boundaries, RV64 word sign extension, and RV32 illegal long operations. Compare the changed native backend against an independent oracle, including FCSR and memory effects.

9. **PPC64’s cache-capacity change can create permanent compile declines.** The arena is already [8 MiB](/Users/angerman/Projects/zw3rk/ppc64rt/src/dbt/cache.c:24), and publication consumes whole host pages per block. On a 16 KiB host, it can hold at most 512 one-page publications. Raising marks from 64 to 4096 exposes the [reserve-failure path](/Users/angerman/Projects/zw3rk/ppc64rt/src/dbt/dbt.c:717), which returns failure without retiring and retrying the exhausted arena. Add safe exhaustion recovery and measure live bytes, page padding, occupancy, resets, and decline reasons. Test more than 512 distinct blocks on Darwin.

   Also correct two P1 descriptions: `dbt_revalidate` is a **pre-publication** check, not a hot-hit `memcmp`; retain it. Prefix truncation must use decoded instruction PCs and lengths rather than `pc + 4*k`, because the decoder supports prefixed instructions.

10. **LoongArch branch and memory lowering need dispatcher changes as well as emitters.** The current [epilogue and dispatch path](/Users/angerman/Projects/zw3rk/loongarch64rt/src/dbt/dbt.c:450) write the sequential PC, so the proposed branch emitter’s chosen target would be overwritten. The [miss handler](/Users/angerman/Projects/zw3rk/loongarch64rt/src/dbt/dbt_mem.c:166) recognizes existing immediate integer forms and computes `r[rj] + imm`; newly emitted indexed and FP accesses need corresponding decode, address, site, and rewind support.

    Test taken and untaken branches, FCC branches, `JIRL` register aliasing, and cold/warm TLB paths for every new memory form, including alignment, cross-page, COW, and code-page writes.

11. **The proposed arenas need an explicit W^X and lifetime contract.** The i686 allocator is not the stated `a32h_wx_alloc`: [engine.c](/Users/angerman/Projects/zw3rk/i686rt/src/dbt/engine.c:507) currently uses an initially 8 KiB mapping, with the shown Linux path requesting RWX. The replacement must establish host-specific RW-to-RX publication and I-cache synchronization, account for host page granularity, and sever all links before reuse or reclamation. Apply the same publication and retirement requirements to MIPS64 and the other proposed arenas; test Linux, Darwin, and hyper-linux paths.

12. **The stated acceptance commands do not establish the claimed difftest parity.** [run_catalogue.sh](/Users/angerman/Projects/zw3rk/rt-series/tools/run_catalogue.sh:283) runs a repository parity script or `make check`; its own summary only checks command exit status. For example, [RV’s smoke suite](/Users/angerman/Projects/zw3rk/rvrt/tests/parity_suite.sh:39) runs loader and signal gates, not the changed DBT. RV’s Darwin `--difftest` path sets a mode and executes the normal DBT, but [does not invoke a comparator](/Users/angerman/Projects/zw3rk/rvrt/src/darwin_main.c:514); its separate [difftest implementation](/Users/angerman/Projects/zw3rk/rvrt/src/dbt/difftest.c:62) exercises the legacy JIT and uses the interpreter for RV32. LoongArch’s current difftest likewise does not compare native JIT register state instruction by instruction.

    Add real changed-backend lockstep on both RV XLENs and LoongArch, with cloned memory and comparisons of PC, registers, FP state, traps, and writes. Require native-execution counters so fallback cannot satisfy the test. Check reported GAPs explicitly: for example, SPARC64’s parity script can [exit successfully with GAPs](/Users/angerman/Projects/zw3rk/sparc64rt/tests/parity_suite.sh:377).

Several lane tasks also need to be rewritten against the current implementation:

- **i686:** Indirect JMP and RET already use `I686_EXIT_BRANCH`, and [the actual trampoline](/Users/angerman/Projects/zw3rk/i686rt/src/trampoline.S:57) already performs IBTC chaining. It does, however, spill and reload all eight guest GPRs on every chained edge and has no visible chain budget or pending-signal check in that loop. Measure that traffic and add bounded polling rather than implementing a second IBTC.
- **MIPS:** MIPS32 already uses `sigsetjmp(..., 0)`; MIPS64 uses `_setjmp` in `src/os/threads.c`. MIPS32 SPECIAL2 and SPECIAL3 operations listed in P4.3 are already dispatched. MIPS64 prefill does not decode every instruction as described. Measure the actual costs before hoisting checkpoints or rewriting existing emitters; keep any checkpoint in a live stack frame.
- **SPARC32:** `FBfcc` already has an emitter. The block-ending treatment of FPU instructions remains a separate issue. PPC32 also already has a code-page occupancy bitmap; reuse its invariant rather than introducing a second potentially divergent map. Check the **whole store range**, including multiword and cross-page stores.
- **RV build:** The lane names the wrong Darwin artifact and does not explicitly build `_build/rvrt-fast-linux-aarch64`, which shares the changed emitter. Record the actual runtime and guest artifact hashes used in each benchmark cell.
- **Ownership:** Expand the cards to include tests and the trampoline, VM, OS copyout, and fault-recovery files that their correctness work requires. Current DBT-only ownership cannot implement several required invalidation and acceptance changes.

Finally, change the master checklist to require **default-off phase instrumentation before fixes**, then comparable before/after measurements for each workload and backend. Capture cache hits and misses, native instructions versus fallback by opcode, chain exits, TLB misses, invalidations, compilation/publication time, and syscall time. Pin guest and runtime hashes, compiler flags, host conditions, and warmup; report the timed samples as well as their minimum. The benchmark is CoreMark-*style*, and its total is a sum of separately selected minima; require a per-workload comparison if “beat QEMU on coremark, chacha20, vfp_simd, calls_ibtc, or syscalls” is the goal.
