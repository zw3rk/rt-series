## Details

**P32-R9-1 — `MAP_FIXED` keeps stale file-backing records.** `vm_mmap2_locked` host-clobbers `[target_va, map_end)` (A1 `mmap(MAP_FIXED)` at [ppc32_vm.c:499-501](file:///Users/angerman/Projects/zw3rk/ppc32rt/src/rt32/ppc32_vm.c); A2 in-place fill at [ppc32_vm.c:465-497](file:///Users/angerman/Projects/zw3rk/ppc32rt/src/rt32/ppc32_vm.c)) and re-records regions at [ppc32_vm.c:519](file:///Users/angerman/Projects/zw3rk/ppc32rt/src/rt32/ppc32_vm.c), but never calls `vm_file_untrack_range`, unlike the munmap path at [ppc32_vm_regions.c:802](file:///Users/angerman/Projects/zw3rk/ppc32rt/src/rt32/ppc32_vm_regions.c). Repro: `mmap` a file privately, then `MAP_FIXED|MAP_ANONYMOUS` over half of it; a later `ftruncate` on the file still matches the stale `(dev,ino)` record and zeroes/traps the now-anonymous pages via `file_truncate_phase2`. Fix: `vm_file_untrack_range(target_va, map_end)` after the capacity checks, before the host mapping, mirroring `vm_munmap_locked`.

**P32-R9-2 — `MAP_FIXED` keeps stale LL/SC reservations.** `vm_mprotect_locked` ([ppc32_vm.c:611](file:///Users/angerman/Projects/zw3rk/ppc32rt/src/rt32/ppc32_vm.c)), `vm_munmap_locked` ([ppc32_vm_regions.c:821](file:///Users/angerman/Projects/zw3rk/ppc32rt/src/rt32/ppc32_vm_regions.c)), and `brk` shrink ([ppc32_vm.c:304](file:///Users/angerman/Projects/zw3rk/ppc32rt/src/rt32/ppc32_vm.c)) all call `vm32_ll_note_remap`; `vm_mmap2_locked` has none. Repro: `lwarx` an all-zero page, `MAP_FIXED` a fresh zero page over it, `stwcx.` with 0 succeeds though the reservation predates the mapping. Fix: `vm32_ll_note_remap()` on the `MAP_FIXED`/`MAP_FIXED_NOREPLACE` success path after the region record.

**P32-R9-3 — `mremap` is dead code from the guest's view.** `ppc32_vm_mremap` is fully implemented ([ppc32_vm.c:670-879](file:///Users/angerman/Projects/zw3rk/ppc32rt/src/rt32/ppc32_vm.c)), `PPC32_NR_MREMAP` is defined, but the `syscalls.c` switch ([syscalls.c:544-738](file:///Users/angerman/Projects/zw3rk/ppc32rt/src/os/syscalls.c)) has no `MREMAP` (or `MADVISE`) case, so every guest `mremap` falls to `default: -ENOSYS`. (`madvise` itself is a defensible `-ENOSYS` stub; only `mremap` is charged because a complete in-tree implementation is unreachable.) Fix: add `case PPC32_NR_MREMAP: ret = (long)(int32_t)ppc32_vm_mremap(ctx,a0,a1,a2,a3,a4);`.

**P32-R9-4 — checked copies bypass EOF-trap state.** `vm_range_prot_ok_locked` ([ppc32_vm_copy.c:29-57](file:///Users/angerman/Projects/zw3rk/ppc32rt/src/rt32/ppc32_vm_copy.c)) consults only the region table, never `vm32_page_is_eof_trap`; `ppc32_vm_copyin_safe`/`copyout_safe` therefore succeed on pages `vm_file_trap_beyond_eof` marked `SIGBUS`. Repro: privately `mmap` a 1-byte file over 2 pages; `copyin` of the second page returns zeros instead of faulting, and a direct-pointer syscall write to a fully-trapped A2 host page (`PROT_NONE` after `vm32_sync_host_range`) crashes the host outside `hostfault_run`. The `mremap` move-path `memcpy` at [ppc32_vm.c:842](file:///Users/angerman/Projects/zw3rk/ppc32rt/src/rt32/ppc32_vm.c) is an additional unguarded reader of such pages. Fix: reject trapped pages in the range check (syscalls approximate with `-EFAULT`).

**P32-R9-5 — unchecked direct guest accesses.** `ppc32_ld/st_be` and `ppc32_put_stat/stat64/timespec/timeval` ([convert.c:186-257](file:///Users/angerman/Projects/zw3rk/ppc32rt/src/os/convert.c)) do raw `memcpy` with at most `ppc32_range_ok` (4 GiB window, no mapped/prot/TASK check). Callers inheriting the gap: `sys_uname` ([syscalls.c:342](file:///Users/angerman/Projects/zw3rk/ppc32rt/src/os/syscalls.c)), 64-bit `clock_gettime` ([syscalls.c:371-375](file:///Users/angerman/Projects/zw3rk/ppc32rt/src/os/syscalls.c)), `proc_copy_vec` (`ld32be` after `range_ok` only, [proc.c:273-277](file:///Users/angerman/Projects/zw3rk/ppc32rt/src/os/proc.c)). Repro: `uname(0xC0000000)` passes `range_ok`, then writes a `PROT_NONE` host page and the translator dies with a host `SIGSEGV` instead of guest `-EFAULT` (`ppc32_syscall` runs outside `ppc32_hostfault_run`). Fix: gate each site with `ppc32_vm_range_prot_ok` (plus the R9-4 trap check) or route through `copyin_safe`/`copyout_safe`.

**P32-R9-6 — SPE auto-detect missing on initial load.** `proc.c:542` redetects after `execve`, but `guest_load` ([main.c:332-376](file:///Users/angerman/Projects/zw3rk/ppc32rt/src/main.c)) never calls it, leaving the `-1` default (`main.c:289`) to behave as classic in `fp_step` and in the `AT_HWCAP` selection ([ppc32_stack32.c:177](file:///Users/angerman/Projects/zw3rk/ppc32rt/src/rt32/ppc32_stack32.c)). Repro: run any e500v2 SPE binary without `--profile spe`; the first `ev*` faults `UNDEF`, while the same binary reached via `execve` classifies correctly. Fix: call `ppc32_proc_redetect_profile(ctx, info.text_start, info.text_end)` in `guest_load` before `ppc32_stack_setup` (which publishes `AT_HWCAP`).

**P32-R9-7 — no attribute-based SPE detection.** The loader handles only `PT_LOAD`/`PT_INTERP`/`PT_PHDR` ([ppc32_elf32.c:295-315](file:///Users/angerman/Projects/zw3rk/ppc32rt/src/rt32/ppc32_elf32.c)); detection is solely the 65536-insn opcode-4 scan ([proc.c:215-228](file:///Users/angerman/Projects/zw3rk/ppc32rt/src/os/proc.c)). Repro: SPE binary whose first 65536 instructions contain no major-opcode-4 word runs as classic and dies `UNDEF` on the first late SPE instruction. Fix: parse `PT_GNU_ATTRIBUTES`/`.gnu.attributes` (`Tag_GNU_Power_ABI_Spe`) or require/keep explicit `--profile` when detection is inconclusive.

**P32-R9-8 — cache-block auxv missing.** The vector at [ppc32_stack32.c:148-195](file:///Users/angerman/Projects/zw3rk/ppc32rt/src/rt32/ppc32_stack32.c) publishes `AT_PHDR/ENTRY/BASE/...` but never entries 19/20/21. Repro: dump guest auxv; `AT_DCACHEBSIZE`/`AT_ICACHEBSIZE`/`AT_UCACHEBSIZE` are absent, so cache-block-sensitive code (`dcbz` sizing, optimized `memcpy`) reads 0. Fix: append the three pairs (e.g. guest CPU line size; confirm 750/e500v2 values against the `qemu-ppc -cpu 750/-cpu e500v2` oracle).

**P32-R9-9 — silent `argv`/`envp` truncation.** `push_string_table` stops at 511 ([ppc32_stack32.c:57](file:///Users/angerman/Projects/zw3rk/ppc32rt/src/rt32/ppc32_stack32.c)) and returns success with the short count. Repro: execute with 600 arguments; guest `argc` is 511 with no error. Fix: fail setup when `strs[cap] != NULL` after the capped scan.

**P32-R9-10 — over-strict segment ordering.** [ppc32_elf32.c:347-351](file:///Users/angerman/Projects/zw3rk/ppc32rt/src/rt32/ppc32_elf32.c) rejects any `p_vaddr < prev_seg_end`, conflating overlap with order. Repro: hand-crafted ELF with two non-overlapping `PT_LOAD`s in descending order loads on Linux but is rejected here. Fix: reject only true overlaps (`seg_vaddr < prev_end && seg_end > prev_start` over all prior segments, or sort-then-check).
