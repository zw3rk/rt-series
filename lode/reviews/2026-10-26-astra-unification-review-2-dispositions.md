## Summary of Review #2 Findings (`B1`–`B14`) & Dispositions in Rev 3

| ID | Severity | `astra` Review #2 Finding Summary | Status in Rev 3 | Resolution in `docs/UNIFICATION-PLAN.md` (Rev 3) |
|---|---|---|---|---|
| **`B1`** | **Critical** | In Class A (`vm32.c`), narrowing a 16 KiB or 64 KiB host page in `[G, G+4GiB)` to `PROT_READ` or `PROT_NONE` causes host syscalls (`read`, `pread64`, `recvfrom`, `getdents64`) or `interp_step` to fault with `EFAULT`/`SIGSEGV` when touching an allowed writable 4 KiB neighbor quarter. | **RESOLVED (Design)** | Replaced with **Dual-View Shared Backing (`G` + `S`)** in **§4.4** (`rt_host_create_dual_window32` in `backend.h`): on >4 KiB hosts, the 4 GiB guest RAM is backed by a `shm_open`/`memfd_create` object mapped at **`G` (`x20`, hardware-protected per host page with `N_sub = H/4096` intersection)** AND **`S` (`ctx->rw_alias_base`, mapped `PROT_READ \| PROT_WRITE` over the exact same physical pages)**. All syscall copyin/copyout (`read`, `pread64`, `recvfrom`, `getdents64`), `interp_step`, instruction fetch, futex, and `sigframe` operations validate `vma_page_prot[vpn]` in software under `RT_WORKER_SYSCALL_LEASE` and read/write **`S + gva`**, never faulting on narrowed `G` pages or widening `G`. |
| **`B2`** | **Critical** | The epoch quiescence protocol let acknowledged workers immediately resume and refill their Soft-TLB from the old VMA table while the mutating thread was still reclaiming host backing, and did not drain workers holding guest pointers inside syscalls. | **RESOLVED (Design)** | Specified the **5-Step Two-Phase Stop-The-World Quiescence Transaction + Syscall Memory Leases** in **§4.3.4**: (1) set `g_vm_mutating = 1` under `g_vm_mutation_lock` (blocking all `.L_tlb_miss_site_k` refills and new `RT_WORKER_SYSCALL_LEASE` entries); (2) request yield and wait until all sibling workers reach `RT_WORKER_PARKED` and active syscall memory leases drain to 0 (blocking syscalls never hold raw guest pointers across blocking waits); (3) mutate VMA/inode tables, invalidate DBT blocks, and flush parked workers' `ctx->tlb[]`; (4) execute host `mprotect`/`munmap`; (5) clear `g_vm_mutating = 0` and broadcast `g_vm_park_cond`. |
| **`B3`** | **Major** | The Soft-TLB store listing said "use `[x2, #8]` for stores" while retaining `ldp x2, x3`, which loads `addend` (`+8`) into `x2` (the tag comparison register) and `write_tag` (`+16`) into `x3` (the addend register). | **RESOLVED (Design)** | Published separate, complete 7-instruction **Load** (`ldp x2, x3, [x2, #0]`) and **Store** (`ldp x3, x2, [x2, #8]` — swapped destination pair!) listings in **§4.3.2**, with `reg_val` (`x0`) disjoint from `reg_addr` (`x1`) and scratch (`x2, x3, x4`). |
| **`B4`** | **Major** | Signed load extensions (`ldrsb`/`ldrsh`/`ldrsw` to 64-bit `X` regs, big-endian `rev16`/`rev` followed by `sxth`/`sxtw`) and the `.L_tlb_miss_site_k` / instruction-7 fault recovery metadata (`dbt_mem_site_t`) needed an explicit specification. | **RESOLVED (Design)** | Added the **Frozen Instruction-7 Lowering Table** (all U8/S8/U16/S16/U32/S32/U64/Store LE & BE sequences) and the **`dbt_mem_site_t` Per-Site Miss Stub & Hardware Fault PC-Recovery Contract** in **§4.3.2–4.3.3** (preserving `NZCV`, store value `x0`, and `guest_pc`/`guest_npc` delay-slot state on both cold misses and instruction-7 hardware faults). |
| **`B5`** | **Major** | Passing a 4 KiB guest file offset to `mmap` fails on 16/64 KiB Linux kernels, host kernel EOF `SIGBUS` / COW is host-page-granular rather than 4 KiB guest-granular, and Class A hardcoded `sub_prot[4]` / `& 3`. | **RESOLVED (Design)** | Updated **§4.2, §4.4, and §5.1**: (1) `N_sub = rt_host_page_size() / 4096` (`1`, `4`, or `16`); (2) Provider A rounds host `mmap` file offsets down to `H = rt_host_page_size()` with a byte `bias` (matching `rvrt_shared.c:94`); and (3) `vm64.c` enforces **4 KiB/8 KiB guest-granule EOF `SIGBUS` (`page_file_offset >= align_up(file_size, GUEST_ABI_PAGE_SIZE)`) and 4 KiB `PAGE_COW_CLEAN` -> `PAGE_COW_DIRTY` promotion in software** inside the Soft-TLB fill and syscall copyout paths. |
| **`B6`** | **Major** | Truncating or overwriting a `PROT_EXEC` mapped file did not specify an inode-to-DBT block invalidation transaction. | **RESOLVED (Design)** | Specified in **§4.3.4 (Step 3)** and **§5.1**: every `dbt_block_t` is indexed by `(backing_inode_id, file_offset_start, file_offset_end, backing_generation)`; `ftruncate`/`write`/`munmap`/`mprotect` on a watched executable backing runs the 5-step stop-the-world transaction, invalidates overlapping DBT blocks, unlinks direct chains, and clears IBTC/RAS before workers resume. |
| **`B7`** | **Major** | `hyper-linux` spawns separate processes on `fork` (`fork_ipc.c:1620`), so a VM-local `hl_inode_backing_t` cannot coordinate cross-fork `ftruncate` invalidation or preserve pre-fork `PTE_COW_DIRTY` provenance. | **RESOLVED (Design)** | Specified **Cross-`fork_ipc` Shared Inode Authority** in **§5.2.1**: `hl_inode_backing_t` keeps `_Atomic uint64_t file_size`, `size_generation`, and `code_generation` in a 4 KiB `MAP_SHARED` `hl_inode_ctrl_t` descriptor exported across `fork_ipc.c` via `SCM_RIGHTS`, alongside the per-page `PTE_COW_CLEAN`/`PTE_COW_DIRTY` bitmap in the `guest_region_t` wire record. |
| **`B8`** | **Major** | Mapping clean writable `MAP_PRIVATE` pages read-only in `hl` Stage-1 PTEs causes host syscall copyouts (`sys_read` at `syscall_io.c:1611`, `sys_recvfrom` at `syscall_net.c:1931`) to either fail Stage-1 write validation or write to `host_base + gpa` without promoting the page to `PTE_COW_DIRTY`. | **RESOLVED (Design)** | Specified **Centralized Host Copyout COW Promotion (`hl_ensure_writable_and_promote_cow`)** in **§5.2.2**: all `hl` host copyout funnels validate `guest_region_t.prot & LINUX_PROT_WRITE`, promote touched `PTE_COW_CLEAN` pages to `PTE_COW_DIRTY` (updating the Stage-1 PTE and setting `SHIM_TLBI_MAILBOX`) before writing bytes, and Wave U4 (`RC-U4`) tests `read`/`recvfrom` into clean `MAP_PRIVATE` followed by partial `ftruncate`. |
| **`B9`** | **Major** | The register table misstated `sparc64rt` (`x19 = ctx, x27 = chain, x28 = epoch`), `ppc64rt` (`x0 = cpu, x1 = mem_ops, x2 = mem_ctx`), and `a32rt` (`w0..w14 = r0..r14`). | **RESOLVED (Design)** | Corrected **§4.1** with exact `file:line` citations to `a32rt/src/a64_emit.h:20-36`, `sparc64rt/src/dbt/trampoline_a64.S:12-44`, and `ppc64rt/src/dbt/trampoline_a64.S:10-42`, distinguishing preserved conventions (`a32rt`, `i686rt`, `rt32`, `sparc64rt`, `loongarch64rt`, `mips64rt`) from `ppc64rt`'s Wave U2 prologue migration (`x19 = cpu, x20 = &cpu->tlb[0]`). |
| **`B10`** | **Major** | Wave U1 called `host_contract_identity.c:452` family creation unused in `sparc64rt`, whereas `sparc64_host_selftest` (`host_contract_identity.c:707`) calls it and `tests/check_host_contract.sh:433` asserts its output. | **RESOLVED (Design)** | Updated **§3** and **Wave U1 (§7)** so `sparc64rt` migrates the full `sparc64_host_selftest` closure into `src/os/host_contract*.c` and requires `sparc64rt/tests/check_host_contract.sh` to pass 100% unmodified in `RC-U1`. |
| **`B11`** | **Major** | `src/os/backend.h` lacked (1) signal-atomic blocking-call commitment (`safe_syscall_a64.S`), (2) canonical shared futex identity (`futex_key.c`), and (3) asynchronous `siginfo_t` fields (sender PID/UID, sigval, timer overrun) + per-worker `sigaltstack`. | **RESOLVED (Design)** | Added `rt_worker_sync_t` (`sig_seq` atomic commit window passed to all blocking calls), `rt_futex_key_t` (`PRIVATE`, `SHARED_ANON`, `SHARED_FILE` with `owner_id`, `mount_id`, `offset`), `rt_host_worker_altstack_{init,destroy}`, and split `rt_host_sync_fault_t` vs `rt_host_async_siginfo_t` in **§6 (`src/os/backend.h` Rev 3)**. |
| **`B12`** | **Major** | Wave gates had inconsistent `0 GAP` vs `0 FAIL` wording, lacked a semantic gate for the Wave U0 prototype, scheduled 3-host dirty-COW acceptance in U2 before Provider B (U4), and omitted continuous AOT gates in U1/U2/U4. | **RESOLVED (Design)** | Updated **Waves U0–U6 (§7)**: enforced the strict **Zero-GAP Rule** across `RC-U0..RC-U6`, added an explicit `loongarch64rt` Soft-TLB + `backend_darwin.c` torture gate in `RC-U0`, staged Provider A (`RC-U2`) vs Provider B (`RC-U4`) COW acceptance, and added explicit AOT preservation checks to every wave gate (`RC-U1` through `RC-U6`). |
| **`B13`** | **Minor** | The `src/rt64/` donor file/LOC partitions in §3 used working-tree subsets rather than pinned `git ls-tree` blobs (`loongarch64rt` 81/27,969; `mips64rt` 81/28,355; `ppc64rt` 242/54,930; `sparc64rt` 252/57,529; sum = 168,783 LOC). | **RESOLVED** | Replaced the counting script and table in **§3** with exact `git ls-tree -r --name-only <rev> src include` + `git show <rev>:<path>` counts matching all four verified donor partitions (`81 / 27,969`, `81 / 28,355`, `242 / 54,930`, `252 / 57,529`). |
| **`B14`** | **Minor** | The `>99%` uniform 16 KiB page claim in §4.4 lacked workload measurements. | **RESOLVED** | Removed the unmeasured percentage in **§4.4** and required Wave U3 to instrument `ctx->stats.mixed_page_traps` vs total memory accesses. |
