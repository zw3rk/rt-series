**Medium — `mremap` rejects valid protected mappings on larger-page Linux hosts.**

The new [remap_copy_span()](/Users/angerman/Projects/zw3rk/mips64rt/src/os/mem_table.c:517) advances in 4 KiB increments and calls raw `mprotect(hp, 4096, PROT_READ)` for non-readable pages.

A concrete failure sequence:

1. On native Linux with 16 KiB or 64 KiB host pages, create a host-page-aligned anonymous `PROT_NONE` mapping of one host page.
2. Move it to a disjoint, equally aligned destination using `MREMAP_FIXED | MREMAP_MAYMOVE`, preserving its size.
3. The second snapshot iteration calls `mprotect(source + 4096, ...)`. That address is not host-page aligned, so Linux returns `EINVAL`.
4. The translator returns this error instead of completing the valid move.

The baseline protected the entire aligned source span, so this case previously worked. Native larger-page Linux is within the specified support scope.

Perform temporary protection changes over host-page-aligned spans while preserving surrounding permissions. This finding was independently cross-checked from source, not runtime-reproduced.
