# Round-5 Post-Remediation Verification: `ppc64rt` @ `605b509`

**Scope and method.** Static inspection of commit `605b509` ("Round-5 defect remediation (P64-R5-1..R5-10)") against the astra checklist. Four shell turns, no builds, tests, containers, or QEMU. HEAD equals `605b509` and the working tree has no diff against it, so all line references are to the audited commit.

**Headline.** 6 items VERIFIED, 2 PARTIAL, 1 NOT FIXED, 1 REGRESSION. The regression is serious: the R5-10 cleanup now passes `NULL` into two helpers that still dereference it, so every interpreted `stfd`/`stfs`/`stvx` will crash the host process.

## Required follow-ups

1. **R5-10 (High, blocking).** Either NULL-guard `src/interp/vec.c:351` and `:422`, or, better and in the spirit of the finding, delete the `res_valid` parameter from `ppc64_exec_prefixed`, `ppc64_exec_vec`, and `ppc64_exec_fmove` (prototypes at `src/interp/interp.c:90-97`) and all the now-dead `if (res_valid != NULL)` blocks in `prefix.c`. Run `tests/test_p3_fp_simd.c` as the regression.
2. **R5-4 (High).** In `src/interp/prefix.c:115-129` use `cpu->vsr[rt + 32u]`, write `[0]` from memory and zero `[1]`. Add a negative and an even-RA case to the oracle.
3. **R5-8 (Medium).** Port `tests/check_host_contract.c` and the `p6_probe.c` heredoc to the current `vm/`, `dbt/aot/`, and `vm_file_*` APIs, or delete the two compile stages and route the checks through a maintained Make target. Today the scripts advertise a check that cannot compile.
4. **R5-6 (Medium).** After the `pwrite` loop at `src/vm/vm_file.c:719-730`, surface `done < n` explicitly (return status to the fault hook, or at minimum a counted diagnostic) so lost persistence is observable.
5. **New: P64-R5-11 candidate (Medium).** `src/interp/prefix.c:209` still derives a TX bit from suffix bit 16 (RA's low bit) for the 8LS `PLXV`/`PSTXV` path at `:314-319`. In ISA 3.1 the TX bit is suffix primary-opcode bit 5, so `XT >= 32` forms carry suffix opcode 51/55. `src/interp/decode.c:650` and `:652` match only 50/54, so those forms are rejected as illegal while the odd-RA aliasing remains for the accepted forms.

## Hygiene

- **Line limits.** All ten touched files are within bound. Largest is `src/vm/vm_file.c` at 822 lines; `src/interp/interp.c` 758, `src/interp/decode.c` 698, `src/os/syscalls_mm_map.c` 662. None exceeds 900. `src/interp/vec.c` is untouched.
- **Curated C11.** The diff introduces no VLAs, no `sprintf`/`strcpy`/`strcat`, no Annex K, no `_Generic`, no `<threads.h>`. Declarations sit at block heads. Arithmetic in the R5-7 and R5-1 fixes is unsigned. `fcntl` return values are checked before use. No concerns.
- **Unverified.** No compile or test execution. The DBT `default:` at `src/dbt/emit_mixed.c:306` is assumed to return false and fall back to the interpreter for `PPC64_OP_PLXSD`. Existence of `src/core/profile.h` and `src/os/sigframe_ppc64rt.h` for the R5-8 harness was not checked, since the `memory/` and `aot/` includes already fail. Whether `mprotect` can later raise a `MAP_SHARED` mapping of an `O_RDONLY` fd to `PROT_WRITE` (Linux `VM_MAYWRITE` rule) was not examined and is outside R5-5's stated scope.

**Recommendation.** Do not close Round 5 for `ppc64rt`. Fix item 1 first since it breaks the correctness oracle for all FP and vector stores, then items 2 through 4, and re-run the fp/simd and prefix oracle suites before re-review.
