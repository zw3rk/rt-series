## Section 3: Remaining or Newly Introduced Consequential Findings

1. **Medium — BUG (new) — `mremap` growth can shrink a shared-anonymous backing.** `src/rt32/ppc32_vm.c:733-742`. For `MAP_SHARED|MAP_ANONYMOUS` regions, growth calls `ftruncate(mremap_fd, orig_offset + new_aligned)` without consulting the current file size. After a split (e.g. `mprotect` yields `[0,8K)` at offset 0 and `[8K,32K)` at offset 8K over one 32K backing), remapping the first fragment from 8K to 12K truncates the file to 12K, so pages 12K..32K of the sibling region fall beyond EOF: subsequent access raises SIGBUS and the data is destroyed. Fix: `fstat` first and only `ftruncate` when `req_sz > st_size`.

2. **Medium — BUG (new, A2 hosts only, host page > 4 KiB) — `shared_direct` host-maps a rounded length without checking the tail.** `src/rt32/ppc32_vm.c:435-443`. `host_map_len` is rounded up to the host page, and the direct `MAP_FIXED` `mmap` covers it, but only the `MAP_FIXED` guest-requested range `[target_va, map_end)` was checked for conflicts/capacity. A host-aligned `MAP_FIXED|MAP_SHARED` request shorter than a host page clobbers the neighbouring guest mapping at host level while region metadata still advertises it. In the non-fixed path the tail `[map_end, target_va+host_map_len)` is file-backed on the host but unrecorded; the 4 KiB-aligned fallback gap scan can later assign it to a private mapping, which `vm32_sync_host_range` then `mprotect`s over the file-backed page (aliasing). Fix: require the full `host_map_len` range to be free (fixed path) and record or reserve the tail (gap path). Verdict: PLAUSIBLE (static; A2 not exercised here).

3. **Low — DEFECT — per-region descriptor ownership is unbounded relative to `RLIMIT_NOFILE`.** Each region (not each backing) holds a dup; with `PPC32_MAX_REGIONS = 512` allocated from fd 512 upward, a guest with many file-backed segments plus its own fds can hit the default 1024 soft limit, surfacing as spurious `-ENOMEM` from `mmap`/`mprotect` splits (`vm_insert_region_raw_ex` fails on dup). The audit's recommended refcounted backing object (one fd per backing) would bound this. Related residual: the host fd namespace is shared with the guest, so a guest `close_range`/close-sweep above 512 can still revoke a region's private fd; full isolation is out of this round's scope but should be tracked.

4. **Low — DEFECT — residual validation-to-copy window in `signals.c`.** `sig_range_prot_ok` validates under the VM lock, but `sig_ld32`/`sig_st32` copy after release. The same class the audit called out for `threads.c`; switch these sites to `ppc32_vm_copyin_safe`/`copyout_safe`.

5. **Low — CLEAN.** (a) `vm_create_shared_anon_fd` uses an `mkstemp` file in `/tmp` although the repo already uses `memfd_create` in `backend_linux.c` and `procfs.c`; prefer memfd on Linux with the mkstemp fallback for Darwin to avoid `/tmp` ENOSPC/unwritable failures and disk-backed shared memory. (b) `g_vm_root_ctx` is now write-only. (c) The inline DBT SUBFME/SUBFZE OV sequence in `ei_addsub_xo` is unreachable after the new fallback. (d) The addend-is-base invariant that makes the lock-free A64 TLB fast path sound is still undocumented.

**Recommended follow-up order:** fix #1 (one-line guard), then #2, then re-run the Docker `check_p32_defects` and the qemu parity suite on the integrated result before closing Round 2.
