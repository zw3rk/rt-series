## 2. Mandatory Cross-Lane Correctness Invariants (Reconciled from `astra` + `fable` Reviews)

Every worker lane MUST enforce the following 10 invariants identified during the dual `astra` and `fable` reviews:

1. **AAPCS64 Callee-Saved `d8..d15` + Write-Through for Scalar FPR Caches (`ppc64rt`, `loongarch64rt`, `mips64rt`, `sparc32rt`, `sparc64rt`)**:
   - Both `astra` and `fable` noted that `v16..v31` (`d16..d31`) are **caller-saved** in AAPCS64, so any C helper (`tlb_miss`, `divdo`, `fp_sync_fsr`, `sparc32_rt_store`, etc.) can clobber `d16..d31`, and a lazy dirty FPR cache would lose state if a mid-block load/store faults and exits the block!
   - **Mandatory Solution**:
     1. Use **AArch64 callee-saved `d8..d15`** (the low 64-bit scalar doubles of `v8..v15`, which AAPCS64 guarantees every C function preserves!) for the 8-slot scalar FPR cache in `ppc64rt`, `loongarch64rt`, `mips64rt`, `sparc32rt`, and `sparc64rt`. Save and restore `d8..d15` (`4` `stp`s / `4` `ldp`s) once in `trampoline_a64.S` (if not already saved there).
     2. Make the 8-slot `d8..d15` FPR cache **write-through** (just like `ppc64rt` and `sparc64rt`'s GPR caches): every scalar FPR write updates `d(8+slot)` via `FMOV` (or writes directly into `d(8+slot)`) **AND** emits the store to `ctx->fpr[]` / `ctx->vsr[]` in memory!
     3. Why write-through in `d8..d15` is strictly superior:
        - `ctx->fpr[]` / `ctx->vsr[]` in memory is **always 100% coherent** on every fault, trap, SMC exit, D2 fallback, or C helper call — **zero flush code and zero fault-recovery tables needed**!
        - Every FPR **read** (`FMADD` has 3 reads, `FADD`/`FMUL` have 2 reads, `STFD`/`SDC1` has 1 read) becomes a 0-memory-access register read (`d(8+slot)`), eliminating 75%–100% of all `ctx->fpr[]` memory loads!
        - Bidirectional aliasing with vector/single instructions (`VSX` in `ppc64rt`, `LSX` in `loongarch64rt`, single-precision `f0..f31` in `sparc32rt`/`sparc64rt`, `MTC1`/`LWC1` in `mips64rt`) only needs to **invalidate** (`fpr_valid &= ~(1u << slot)`) when a non-cached instruction writes an aliased register, because `ctx` in memory already holds the latest value!
2. **`ppc64rt` `e_set_nip` Removal Scope & Update-Form Store Ordering (`astra` & `fable` P13-1)**:
   - Only remove fast-path `e_set_nip(e, pc)` on single-access non-update loads/stores in `e_ldst`, `emit_fp_ldst`, and `emit_vsx_mem` that go through `ppc64_mem_emit_site` -> `ppc64_vm_tlb_miss` (where `e->gpr_valid` is write-through and `e->fpr_valid` is write-through).
   - **Keep `e_set_nip(e, pc)`** on update-form loads/stores (`d->upd`, so if an SMC store retires at `pc + 4` in `common`, `rA` has already been updated — or emit `rA` update before the store when `d->upd && d->ra != d->rt`), on `e_atomic`, and on `emit_fp_pair`.
   - In `ppc64_vm_tlb_miss` (`src/vm/vm64.c`), set `cpu->ctx.nip = guest_base + (uint64_t)s->guest_pc_delta` before returning `1` (fault) and `cpu->ctx.nip = guest_base + (uint64_t)s->guest_pc_delta + 4ULL` before returning `2` (SMC retire).
3. **`ppc64rt` `RLWINM`/`RLDIC*` & `RA == 0` Encodings (`astra` & `fable` P13-1)**:
   - In `PPC64_OP_RLWINM` when `d->mb <= d->me`:
     - When `d->mb == 0 && d->me == 31` (`m == 0xFFFFFFFFu`, which is NOT encodable as an AArch64 32-bit logical immediate!): emit `MOV Wd, Ws` (`sh == 0`) or `EXTR Wd, Ws, Ws, #((32 - d->sh) & 31)` (`sh != 0`) with **no `AND`**.
     - When `d->mb == 32 - d->sh && d->me == 31` (`srwi`): the right-shift count is `32 - d->sh` (`d->mb`), i.e., `UBFM Wd, Ws, #(32 - d->sh), #31` (`LSR Wd, Ws, #(32 - sh)`), **NOT** `#d->sh`!
     - Always preserve the `if (d->rc) e_rc0(e, ...)` record-form `CR0` update at the end of `e_rot`.
   - In D-form EA calculation (`e_ldst`, `emit_fp_ldst`, `emit_fp_pair`): when `d->ra == 0`, PowerPC specifies literal `0` (NOT `r0`), whereas AArch64 register `0` is `x0` and register `31` in `ADD`-immediate is `SP`! Therefore, when `d->ra == 0`, always use `e_mov_imm(e, 13, (uint64_t)d->si)`; only use `e_get_gpr(e, d->ra, 13)` + `e_add_imm`/`e_sub_imm` when `d->ra != 0`.
   - Keep `e_prologue` / `e_epilogue` (`stp/ldp x29, x30`) in `ppc64rt` blocks (preserving `LR` across all helper calls and frame pointers), and in `trampoline_a64.S` keep `fast_ibtc` (`[sp, #80]`) in a callee-saved register or avoid redundant stack stores in `.Lchain_loop`.
4. **`ppc32rt` `fp_next_is_arith` Whitelist Excludes `stfs*` (`astra` & `fable` P13-1)**:
   - In `ppc32rt`, `stfs`/`stfsx`/`stfsu`/`stfsux` emit `FCVT S0, D0`, which can set host `FPSR` `IXC`/`UFC`/`OFC` even though PowerPC `stfs` does not modify `FPSCR`. Therefore, **exclude `stfs*` from the transparent lookahead whitelist** (only allow 64-bit `lfd*`/`stfd*`, `lfs*`, `fmr`/`fabs`/`fneg`/`fnabs`, and non-trapping integer ALU ops `addi`/`addis`/`add`/`subf`/`ori`/`or`/`and`/`rlwinm`/`cmp`/`cmpli` to be looked past when scanning for the next `PPC32_OP_FPU_SINGLE`/`DOUBLE` in the block).
5. **`loongarch64rt` Explicit 3-State `FPCR` Machine & `.S` Merge (`astra` & `fable` P13-2)**:
   - Track `uint8_t fpcr_mode` (`0 = FPCR_DEFAULT`, `1 = FPCR_DYN`, `2 = FPCR_FIXED`) in `la64_emit_ctx_t`.
   - `fpcr_enter_dyn_hoisted(e)` transitions `0 -> 1` (emitting `fpcr_enter_dyn(e)` once); fixed-rounding ops (`FTINTRZ`, etc.) transition to `2` and then restore `0` (`msr fpcr, xzr`), so a subsequent `dyn` op re-enters `1`.
   - `la64_emit_flush_fcsr(e)` (called on `MOVGR2FCSR`, FCSR reads, helper calls, and all block exits) emits `fpcr_restore(e)` (`msr fpcr, xzr`) whenever `e->fpcr_mode != 0` and resets `e->fpcr_mode = 0`.
   - In `loongarch64rt`'s write-through `d8..d15` FPR cache, only cache 64-bit `.D` registers (`f_load_d`, `f_store_d`, `FLD.D`, `FST.D`, `FLDX.D`, `FSTX.D`), and invalidate the matching slot (`fpr_valid &= ~(1u << slot)`) on any `.S` write or LSX vector write to that register! (Since `vfp_simd` and hot FP kernels are `.D` or `.S`, wait: what if `.S` is also cached? On `.S` write, `f_store_s` writes `STR St, [x19, #off]` and updates `s(8+slot)`, and we track `uint8_t fpr_is_d` bitmask so `f_load_d` requires `(fpr_valid & fpr_is_d) & (1u << slot)` while `f_load_s` only requires `fpr_valid & (1u << slot)`! That way `.S` never corrupts a subsequent `.D` read's upper 32 bits, and both `.S` and `.D` get 100% cache hits!)
6. **`mips32rt` & `mips64rt` Odd/Even FPR Aliasing & Batch Closure (`astra` & `fable` P13-3)**:
   - In `mips32rt/src/dbt/emit_fp.c:302-304`, when `fn == 0x05 || fn == 0x06 || fn == 0x07` (`ABS`/`MOV`/`NEG`), if `b->fp_batch_open && !b->fp_defer_finish`, call `fp_batch_close(b)` before returning.
   - In `mips32rt/src/dbt/dbt.c`, extend the `next_fp` lookahead across `LWC1`/`LDC1`/`SWC1`/`SDC1` (`0x31`/`0x35`/`0x39`/`0x3D`), `COP1` `MOV`/`ABS`/`NEG`, and non-trapping integer ALU ops (`ADDIU`, `ADDU`, `SUBU`, `ANDI`, `ORI`, `XORI`, `SLL`, `SRL`, `SRA`, `SLT`, `SLTI`, `SLTIU`, `SLTU`), stopping at any branch, `CFC1`/`CTC1`/`MFC1`/`MTC1`/`BC1`, `C.cond.fmt`, `CVT.*`, trap/syscall, or unknown/D2 instruction.
   - Keep `mips32rt`'s `d16..d23` FPR cache **write-through** (`fp_store_d` updates `d(16+slot)` AND writes through to `ctx->fpr[]`), and also populate `d(16+slot)` on `LDC1` and read `d(16+slot)` on `SDC1` (`FMOV`), invalidating the pair slot `(reg & ~1u)` on any single-precision write (`fp_store_w`, `LWC1`, `MTC1`).
   - In `mips64rt`, add a **write-through** 8-slot FPR cache in **callee-saved `d8..d15`** (saved/restored in `trampoline_a64.S`), tracking `fpr_valid` and `fpr_is_d` (`1` = 64-bit `.D`, `0` = 32-bit `.S`), updating `d(8+slot)` on `f_st_d`/`f_st_s`/`LDC1`/`LWC1`/`LDXC1`/`LWXC1` and reading `d(8+slot)` on `f_ld_d`/`f_ld_s`/`SDC1`/`SWC1`/`SDXC1`/`SWXC1`, and invalidating on `MTC1`/`DMTC1`.
7. **`sparc32rt` & `sparc64rt` Exact `NZCV` Condition Table & `CCR`/`PSR.icc` Bit Order (`astra` & `fable` P13-4 & P13-5)**:
   - **Never use raw `LSR/LSL` without bit permutation between SPARC `icc`/`xcc` (`N,Z,V,C`) and AArch64 `NZCV` (`N,Z,C,V`)**: `C` and `V` are swapped in bits 0 and 1! Keep the existing exact `PSR.icc` / `CCR` memory commit (which uses only `CSET`, `LSL`, `ORR`, `BIC`, `STR` — **none of which modify host `NZCV`**!).
   - Track live host `NZCV` origin in the block context (`0 = invalid`, `1 = ADDcc`, `2 = SUBcc`, `3 = Logic cc`):
     - Clear `nzcv_valid = 0` at block entry and inside every emitter helper that modifies host `NZCV` (alignment `TST`, Soft-TLB `CMP`, `FCMP`, `CCMP`, `ADDS`/`SUBS` scratch, C helper calls).
     - Recall that both `sparc32rt` and `sparc64rt` evaluate the branch condition **before** emitting the delay-slot instruction!
     - When `nzcv_valid == 2` (`SUBcc`, which is 99% of SPARC branches via `cmp`): host `NZCV` already has `C = !borrow`, so emit **0 setup instructions** before the branch and map all 16 SPARC conditions directly (`BE`->`EQ`, `BNE`->`NE`, `BLE`->`LE`, `BG`->`GT`, `BL`->`LT`, `BGE`->`GE`, `BLEU`->`LS`, `BGU`->`HI`, `BCS`->`CC`, `BCC`->`CS`, `BNEG`->`MI`, `BPOS`->`PL`, `BVS`->`VS`, `BVC`->`VC`).
     - When `nzcv_valid == 3` (`Logic cc`, where guest `C=0, V=0` and host `TST` sets `C=0, V=0`): for `BE`, `BNE`, `BLE`, `BG`, `BL`, `BGE`, `BNEG`, `BPOS`, emit **0 setup instructions**; for `BLEU` map to `EQ` and `BGU` map to `NE` (`0` setup insns); for `BCS`/`BCC`/`BVS`/`BVC` fall back to `cond_setup`.
     - When `nzcv_valid == 1` (`ADDcc`): for `BE`, `BNE`, `BLE`, `BG`, `BL`, `BGE`, `BNEG`, `BPOS`, `BVS`, `BVC` (the 10 non-carry conditions), emit **0 setup instructions**; for `BCS`, `BCC`, `BLEU`, `BGU` (the 4 carry-dependent conditions), fall back to `cond_setup`.
   - In `sparc64rt` `e_emit_addsubcc`: keep source operands in `ET0` (`x7`) and `ET1` (`x8`) untouched by writing the 32-bit `ADDS/SUBS` result to `w9` (`ES0`) and the 64-bit `ADDS/SUBS` result to `x10` (`ES1`), running 64-bit first and 32-bit second when the upcoming branch in the block tests `%icc` (or 32-bit first and 64-bit second when it tests `%xcc`), committing `CCR` via `CSET`/`ORR`/`STRB` (which never touch `NZCV`), and finally calling `e_set_gpr(b, d->rd, ES1)` (which uses `MOV` + `STR`, never touching `NZCV`) even when `rd == rs1` or `rd == rs2`!
8. **`sparc32rt` `VM32_PROT_FAST_WRITE` Centralization & `SAVE`/`RESTORE` Invariants (`astra` & `fable` P13-4)**:
   - Centralize all updates to `g_vm32_prot[vpn]` and `g_vm32_state[vpn]` in `sparc32rt/src/vm/vm32.c` through a single inline helper `vm32_sync_fast_write(uint32_t vpn)` called at every write site (`vm32_protect`, `vm_mark_code_page`, `vm_smc_invalidate_page`, `vm32_reset`, `vm32_map`, `vm32_unmap`) that maintains bit 3 (`0x08u`):
     `g_vm32_prot[vpn] = (uint8_t)((g_vm32_prot[vpn] & ~0x08u) | (((g_vm32_prot[vpn] & 2u) != 0u && (g_vm32_state[vpn] & RT_PAGE_HAS_CODE) == 0u) ? 0x08u : 0u));`
   - Materialize `g_vm32_prot` into callee-saved `x25` once at trampoline entry in `sparc32rt/src/dbt/trampoline_a64.S` (since `g_vm32_prot` is a fixed global array address and `x25` is already saved/restored by `trampoline_a64.S` and preserved by all C helpers under AAPCS64!).
   - In `sparc32_emit_win_fast` (`SAVE`/`RESTORE`):
     1. Compute `w15 = rs1 + op2` **before** rotating windows (so `rs1 == rd` reads old-window `rs1`).
     2. Flush dirty GPR cache (`sparc32_flush_gpr_cache(b)`) before checking `canrestore` / rotating windows.
     3. Mirror `new_cwp` into both `ctx->cwp` AND `ctx->psr` bits `4..0` (`ctx->psr = (ctx->psr & ~0x1Fu) | new_cwp`, matching `sparc32_rt_window`).
     4. After rotation, write `w15` to `ctx->r[rd]` (if `rd != 0`) and clear **both** `gpr_cache_valid` and `gpr_cache_dirty` for all slots holding windowed registers (`reg >= 8`).
9. **`sparc64rt` `mem_emit_common` Stack Balance & Continuation Safety (`astra` & `fable` P13-5)**:
   - In `sparc64rt/src/dbt/emit_mem.c:368-395` (`mem_emit_common`):
     - Expand the existing `sub sp, sp, #80` frame to `#96` bytes (`16`-byte aligned) and save `stp x7, x8, [sp, #80]` before `x8` is clobbered, restoring `ldp x7, x8, [sp, #80]` before `add sp, sp, #96` on **both** the normal return path AND the `cbnz w0, fault` exit path so `sp` never drifts on a fault!
     - For `sparc64_mem_emit_site`: instead of moving `cont_idx` before `e_set_gpr`, keep `cont_idx` after `e_set_gpr` (so `sparc64_mem_miss` sign-extension/byteswap/pair/atomic semantics are 100% unchanged!), and in the cold per-site miss stub (`emit_mem.c:722-730`), for load sites where `d->rd != 0` is mapped to a cached slot (`b->gpr_slot_reg[slot] == d->rd`), emit `e_ldr_gpr(b, gpr_cache_reg(slot), d->rd)` (and for `LDD`/`LDDA`, also `d->rd + 1` if cached; for `CASA`/`CASXA`/`SWAP`/`LDSTUB`, reload `d->rd` if cached) inside the cold miss stub after `bl common` returns! Then `b->gpr_cache_valid` never needs to be cleared on any load or store!
   - In `sparc64_fast_win`: check whether `offsetof(sparc64_cpu_t, win_file) - offsetof(sparc64_cpu_t, ctx)` fits in `ADD` (`<= 4095` or `ADD + ADD lsl #12`, which is 2 instructions instead of 4 `MOVZ/MOVK`), and clear `gpr_cache_valid` for windowed registers (`reg >= 8`) whenever `sparc64_fast_win` runs (including in delay slots).
   - In `win_spill_to` / `win_fill_from` (`src/interp/interp_win.c`): apply `SPARC64_STACK_BIAS` (`2047`) once if not already applied by caller (note: callers pass `sp + SPARC64_STACK_BIAS` as `addr`), check `(addr & 7ULL) == 0 && (addr & 0xFFFULL) <= (4096ULL - 128ULL)`, and use the exact `SPARC64_TLB_MASK` and `vpn_and_flags` comparison from `vm64.c`, reading/writing via `memcpy` + `__builtin_bswap64`.
10. **`rvrt` 16-Slot FPR Cache Store Optimization & `i686rt` XMM Cache Encodings (`astra` & `fable` P13-6)**:
    - In **`rvrt/src/darwin_dbt.c`**:
      - Keep `emit_inline_load` (`FLW`/`FLD`) write-through (`clean` in `d(16+fslot)`, so the cold miss path has zero stale-dirty hazard), AND on `FLW` hit emit `ORR x3, x3, #0xFFFFFFFF00000000` (`0xB26083E3u`) + `FMOV d(16+fslot), x3` + `STR x3, [x21, #off]` (saving 1 instruction vs two `MOVK`s and keeping `d(16+fslot)` properly NaN-boxed!).
      - In `emit_inline_store` (`FSW`/`FSD` at `darwin_dbt.c:396-405`): **before** emitting the TLB address/tag probe (`x2`/`x3`), resolve `fslot = dbt_fpr_slot(b, insn->rs2, false)` (so any eviction happens before `x2`/`x3` are live!). Then, inside the store fast path, read `w2`/`x2` directly from `s(16+fslot)`/`d(16+fslot)` via `FMOV w2, s(16+fslot)` (`FSW`) or `FMOV x2, d(16+fslot)` (`FSD` when `fpr_cache_is_d & (1u << fslot)`, or `FMOV w2, s(16+fslot); ORR x2, x2, #0xFFFFFFFF00000000` when single), **without** flushing `rs2` to `ctx->f[rs2]` and reloading from memory on the fast path!
    - In **`i686rt/src/dbt/emit_sse.c`**:
      - First split `src/dbt/emit_sse.c` cleanly into `src/dbt/emit_sse.c` and `src/dbt/emit_sse2.c` (updating `Makefile`) so every file is well below `<= 900` lines.
      - Cache `xmm0..xmm7` 1-to-1 in **write-through** mode in `v16..v23` (`uint8_t xmm_valid` in `i686_emit_ctx_t`):
        - On any XMM read (`q_ldr`, `d_ldr`, `s_ldr`), if `e->xmm_valid & (1u << reg)` is set, copy from `v(16+reg)` (`ORR Vd.16B, V(16+reg).16B, V(16+reg).16B` for 128-bit, `FMOV Dd, D(16+reg)` for 64-bit, `FMOV Sd, S(16+reg)` for 32-bit) in **1 instruction with 0 memory loads and 0 `sse_addr` `ADD`s**! If not valid, load `LDR Q(16+reg), [x9]`, set `e->xmm_valid |= (1u << reg)`, and copy to `Vd`.
        - On any XMM write (`q_str`, `d_str`, `s_str`), write through to `[x9]` in memory (so `ctx->xmm[]` is 100% up-to-date on any fault, signal, `FXSAVE`, or helper exit!) AND update `v(16+reg)`:
          - Full 128-bit write (`q_str`): `ORR V(16+reg).16B, Vs.16B, Vs.16B`, `e->xmm_valid |= (1u << reg)`.
          - Scalar 64-bit write preserving upper 64 bits (`d_str` when `reg` is already valid in `v(16+reg)`): `INS V(16+reg).D[0], Vs.D[0]` (`0x6E080400u | (vs << 5) | (16u + reg)`).
          - Scalar 32-bit write preserving upper 96 bits (`s_str` when `reg` is already valid in `v(16+reg)`): `INS V(16+reg).S[0], Vs.S[0]` (`0x6E040400u | (vs << 5) | (16u + reg)`).
          - Memory `MOVSS`/`MOVSD` / `MOVQ` writes that zero upper bits up to 128: `FMOV S(16+reg), Ss` / `FMOV D(16+reg), Ds`, `e->xmm_valid |= (1u << reg)`.
        - Clear `e->xmm_valid = 0` after any C helper call (`sse_flags_sync` in `COMISS`/`UCOMISS`/`COMISD`/`UCOMISD`) and on `FXRSTOR`.
