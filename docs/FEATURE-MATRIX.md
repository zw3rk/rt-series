## 3. Three-Target Host & Backend Deployment Matrix (`Linux aarch64` × `hyper-linux (hl)` × `Standalone macOS arm64`)

Every translator in `rt-series` supports **two host OS backends** (`src/os/backend_linux.c` and `src/os/backend_darwin.c`) and **three execution environments**:

1. **Standalone Linux `aarch64` (`Backend 1` + `Provider A`)**: Static-PIE `aarch64-unknown-linux-musl` ELF running directly on an `aarch64-linux` kernel (4 KiB, 16 KiB, or 64 KiB host pages) with user-space `Provider A` (`src/vm/vm_file.c`) in-place non-relocating COW, family shared-memory inode/EOF tracking, and `tgkill(..., SIGUSR2)` 6-step quiescence.
2. **`hyper-linux` (`hl`) on Apple Silicon (`Backend 1` + `Provider B`)**: The same static-PIE `aarch64-linux` translator ELF dispatched automatically by `hl` (`hl_translators[]` in `../hyper-linux-u4` @ `cd86f55`), accelerated by `Provider B` (`src/inode_backing.c` VMM-side Stage-1 L3 PTE COW repointing, `hv_vcpus_exit` hardware vCPU preemption, shared DBT invalidation ring, and `hyper-linux-apfs-acl-v1` AOT cache authority).
3. **Standalone macOS `arm64` (`Backend 2` + `Provider A`, no VM)**: Native macOS `arm64` (`Mach-O`) translator running directly on Darwin (`16 KiB` host pages) with `src/os/backend_darwin.c` (Mach/BSD syscall translation, `MAP_JIT` + `pthread_jit_write_protect_np` APRR W^X, `pthread_kill(..., SIGUSR2)` 6-step quiescence, and `Provider A` `vm_file.c` over 7-instruction `4 KiB`/`8 KiB` Soft-TLB).
